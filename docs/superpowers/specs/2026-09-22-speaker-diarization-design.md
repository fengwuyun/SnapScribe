# SnapScribe 说话人识别与批量改名设计

## 1. 目标

为导入音视频和软件录音增加可选的本地说话人分离能力，自动将转录内容标记为“说话人 1 / 说话人 2 / …”，并允许用户在项目详情中一次修改某个说话人的全部显示名称，例如把所有“说话人 1”改为“刘德华”。

本功能识别的是匿名说话人分组，不做人声实名识别，不建立跨项目声纹库。

## 2. 已确认的产品决策

| 项目 | 决策 |
| --- | --- |
| 使用范围 | 导入音视频、软件录音均支持 |
| 开启方式 | 按需开启，默认关闭，不增加上传确认步骤 |
| 说话人数 | 自动判断，不要求用户预先填写 |
| 默认名称 | 说话人 1、说话人 2、说话人 3…… |
| 实时录音 | 15 秒切片先显示临时标签，录音结束后用完整音频统一校正 |
| 批量改名 | 修改稳定说话人 ID 对应的显示名称，不逐段重写文本 |
| 失败策略 | 说话人识别失败不影响转录文本保存和查看 |
| 旧项目 | 无说话人字段时按普通转录显示，无需迁移文件 |

## 3. 技术方案

采用 Sherpa-ONNX 离线说话人分离：pyannote segmentation 模型负责检测说话区间，3D-Speaker 模型提取说话人向量，聚类器自动生成匿名说话人编号。官方提供离线说话人分离 C/C++ API、进度回调和自动统计结果中的说话人数，适合现有 Windows + Tauri + Rust 的本地处理方式。

实现形式使用独立的原生 sidecar 程序：

```text
SnapScribe Rust 后端
  ├─ 现有 FFmpeg：统一生成 16 kHz 单声道 WAV
  ├─ 现有 SenseVoice sidecar：生成带时间戳文本
  └─ 新增 diarization sidecar：输出说话人时间区间 JSON
```

选择 sidecar 而不是直接把 C API 链接进 Tauri 主进程，原因是可以沿用当前 ASR 子进程的启动、取消、错误收集与打包方式；模型或原生运行库异常也不会直接拖垮桌面主进程。

模型和运行文件放入现有资源目录：

```text
src-tauri/resources/bin/sherpa-onnx-diarization.exe
src-tauri/resources/bin/<所需 DLL>
src-tauri/resources/models/speaker-segmentation/model.onnx
src-tauri/resources/models/speaker-embedding/model.onnx
```

打包前必须核对选定模型和二进制依赖的许可证，并记录新增安装包体积。

参考：

- https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/index.html
- https://k2-fsa.github.io/sherpa/onnx/c-api/html/speaker_diarization.html

## 4. 数据结构

### 4.1 转录文档升级

`transcript.json` 的 `schemaVersion` 从 1 升到 2。新增字段全部提供默认值，因此旧文件可直接反序列化。

```ts
interface TranscriptSegment {
  id: string;
  start: number;
  end: number;
  text: string;
  speakerId?: string;
}

interface TranscriptSpeaker {
  id: string;          // 稳定 ID，例如 speaker-1
  name: string;        // 可编辑显示名称，例如 刘德华
  colorIndex: number;  // 稳定颜色序号
}

interface TranscriptDocument {
  schemaVersion: 2;
  projectId: string;
  revision: number;
  segments: TranscriptSegment[];
  speakers: TranscriptSpeaker[];
}
```

批量改名只更新 `speakers[].name`。所有带相同 `speakerId` 的段落立即显示新名称，避免遍历并改写大量文本段。

### 4.2 项目状态

项目增加可选说话人识别状态：

```ts
type DiarizationStatus =
  | "disabled"
  | "provisional"
  | "processing"
  | "completed"
  | "failed";

interface DiarizationState {
  enabled: boolean;
  status: DiarizationStatus;
  error?: string;
}
```

`failed` 只表示说话人标签不可用，项目转录状态仍可为完成。

## 5. 处理流程

### 5.1 导入音视频

```text
读取“区分说话人”开关
  → 创建项目并立即开始转录
  → 现有 ASR 持续产生文本和时间戳
  → 开启时并行准备完整 16 kHz 单声道音频
  → ASR 完成后运行完整音频说话人分离
  → 按时间重叠把 speakerId 合并到文本段
  → 原子保存 transcript.json
  → 状态变为 completed
```

文本段与说话人区间按重叠时长匹配：选择与文本段重叠时间最长的说话人。若没有有效重叠则不写 `speakerId`，界面显示“未识别说话人”。

当前 SenseVoice 在部分运行时只返回一个窗口级文本段，无法可靠地把同一段文字拆给多个说话人。因此第一版不凭空拆词；对跨越多个说话人的窗口先使用主导说话人。后续若 ASR 输出更细的 SRT cue，会自然提高匹配精度。这个限制需要在验收样本中重点检查。

### 5.2 软件录音

录音仍按现有 15 秒切片转录，不改变近实时字幕速度。

```text
每个 15 秒录音切片
  → ASR 输出文本
  → 开启时对切片运行临时说话人分离
  → 用说话人向量与当前会话登记表匹配
  → 显示临时“说话人 N”标签

停止录音
  → 对已保存的完整录音运行一次完整分离
  → 重新建立全局 speakerId
  → 校正所有临时标签
  → 保存最终结果
```

实时标签属于临时结果，界面在录音期间显示“说话人识别中”；停止后显示“正在校正说话人”。完整校正成功后才显示稳定标签。若校正失败，保留临时标签和全部文本，同时显示非阻断错误提示。

### 5.3 暂停、取消和删除

- 暂停转录时不启动新的 ASR 或说话人任务；当前原生子进程结束后进入暂停状态。
- 取消时终止当前 ASR/说话人 sidecar，保留已生成的文本及已有临时标签。
- 删除或移动原始媒体不删除转录文本、说话人标签和自定义名称。
- 重新关联媒体只恢复播放能力，不自动重做说话人识别。

## 6. UI 与交互

### 6.1 首页

在拖拽上传区下方和“开始录音”入口附近增加一个紧凑开关：

```text
[ ] 区分说话人   自动标记说话人 1、说话人 2……
```

开关默认关闭。用户选择文件或开始录音时直接读取当前值，不新增确认弹窗。

### 6.2 转录进度

原有进度阶段扩展为：

- 正在转录
- 正在识别说话人
- 正在校正说话人

说话人阶段仍可暂停或取消。转录文本已经生成时，应继续显示文本，不能用全屏加载替换内容。

### 6.3 项目详情

每段文本布局调整为：

```text
00:17  [说话人 1]  这里是这一段转录文本……
```

- 同一说话人使用稳定的主题色浅色标签。
- 单击文本仍跳转到该段开始时间。
- 双击仍复制该段，内容包含时间戳和说话人名称。
- 鼠标拖选和右键复制保持浏览器原生行为。
- 未启用识别的旧项目不显示空标签，不改变现有布局。

工具区新增“管理说话人”。点击后打开弹窗，列出当前项目的全部说话人：

```text
管理说话人

说话人 1  [刘德华              ]
说话人 2  [说话人 2            ]

                         取消  保存
```

名称输入支持原地修改，保存时一次提交完整映射。名称不能为空；去除首尾空格；允许不同说话人使用相同显示名，但保存前给出弱提示，避免误合并认知。关闭弹窗不保存未提交内容。

### 6.4 复制、导出和 AI 总结

有说话人标签时，全文复制和 TXT 导出格式为：

```text
[00:17] 刘德华：这里是这一段转录文本。
```

SRT 保持标准时间轴格式，把说话人名称放在字幕正文前：

```text
刘德华：这里是这一段转录文本。
```

生成 AI 总结时使用当前说话人显示名称。批量改名后不自动重新生成已经保存的总结；用户再次点击生成时使用新名称。

## 7. 后端命令与事件

新增或调整接口：

```text
start_transcription(path, diarizationEnabled)
recording_start(diarizationEnabled)
project_update_speakers(projectId, speakers)
```

进度事件的 `stage` 增加：

```text
diarizing
reconcilingSpeakers
```

现有 `transcript://segments` 保持兼容；实时临时标签通过同一段结构的 `speakerId` 返回。最终校正完成后发送一个完整文档刷新事件，避免把逐段修正误认为新增段落。

## 8. 兼容与错误处理

| 情况 | 行为 |
| --- | --- |
| 旧 `schemaVersion: 1` 文档 | `speakers=[]`，段落无 `speakerId`，正常显示 |
| 未开启说话人识别 | 完全沿用现有转录路径 |
| 模型文件缺失 | 文本继续完成，项目记录说话人识别失败 |
| sidecar 启动/推理失败 | 保存文本，显示可关闭的错误提示 |
| 自动聚类无法稳定区分 | 保留可确定标签，不确定段不标记 |
| 录音最终校正失败 | 保留临时标签，不覆盖为空 |
| 改名保存失败 | 弹窗保留输入值并显示错误，不局部更新页面 |

## 9. 验收标准

1. 未开启说话人识别时，导入、录音、暂停、取消、编辑、播放行为与现版本一致。
2. 开启后，双人和三人样本可自动生成稳定的“说话人 N”标签，用户无需填写人数。
3. 将“说话人 1”改为“刘德华”后，该项目所有对应段、全文复制、TXT/SRT 导出和下一次 AI 总结输入都使用“刘德华”。
4. 批量改名不改变段落文本、时间戳、播放跳转位置和其他说话人的名称。
5. 录音期间可以看到临时标签；停止后自动进入校正阶段并刷新最终标签，页面不跳不闪。
6. 模型缺失、推理失败或用户取消时，已经生成的转录文本仍可保存、打开、编辑和导出。
7. v0.1.6 旧项目可以直接打开，不出现反序列化错误或空白说话人占位。
8. 安装包包含全部本地模型和运行库；在无 Python、无网络环境的干净 Windows 机器上可以运行。

## 10. 实施边界

本阶段包含匿名说话人分离、自动人数、实时临时标签、停止后校正、批量改名、展示及导出联动。

本阶段不包含实名声纹识别、跨项目记住某个人、手工合并/拆分说话人、逐段单独改说话人、多人同时说话的多标签展示，以及云端说话人识别服务。
