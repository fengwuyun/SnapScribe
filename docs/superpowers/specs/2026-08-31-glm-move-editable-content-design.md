# SnapScribe 默认 GLM、文件移动与可编辑内容设计

**状态：** 已确认，等待实施计划  
**日期：** 2026-08-31  
**基线：** `main@5fbaba3` / SnapScribe `0.1.5`

## 1. 目标

在不推翻现有项目存储、多模型故障转移和文件详情页面的前提下，增加四项能力：

1. 自动为所有用户加入 GLM 4.7 Flash 免费模型预设，用户只需填写 API Key。
2. 导入策略增加“移动到 SnapScribe”，成功后删除原位置文件，并让项目媒体与转录数据集中保存在同一项目目录。
3. AI 总结中的待办事项支持新增、删除、原地编辑、自动保存和完成状态。
4. 转录文本与 AI 总结支持鼠标拖选、快捷键、右键和双击复制，同时保留转录段落的单击跳转播放。

本阶段先完成设计与实施计划，不修改功能代码。

## 2. 已确认的产品决策

1. GLM 4.7 Flash 预设自动加入所有用户，包括已有配置的用户。
2. GLM 预设排在模型列表第一位；填写有效 API Key 后成为首选可用模型。
3. 未填写 GLM API Key 时显示“待配置”，生成总结时跳过该模型，不阻断后续模型故障转移。
4. “移动到 SnapScribe”是移动语义：成功后原位置不再保留文件，SnapScribe 内只保留一份。
5. 文件移动必须先完成目标文件写入和校验，最后才删除源文件，避免中途失败造成数据丢失。
6. 每个转录项目使用独立目录，项目媒体、转录数据和 AI 总结都位于该项目目录内。
7. 设置页“数据保存位置”旁增加“打开当前文件夹”按钮，打开当前生效的数据根目录。
8. 待办文字使用类似 TXT 的直接编辑体验：输入框默认可编辑，失焦自动保存。
9. 转录段落单击仍跳转到音频对应开始时间；双击复制整段。
10. 用户可以拖选部分文字后按 `Ctrl+C` 或右键复制。

## 3. 范围

### 3.1 本次包含

- GLM 4.7 Flash 系统预设及已有用户幂等迁移。
- GLM 预设的简化 API Key 配置流程。
- `reference / copy / move` 三种导入策略。
- 跨磁盘、同磁盘一致的安全移动流程。
- 打开当前数据保存目录。
- AI 待办事项结构化存储与旧数据迁移。
- 待办新增、删除、原地修改、完成/取消完成。
- 转录文本与 AI 总结的选择和复制交互。
- 与上述行为相关的前端、Rust 和迁移测试。

### 3.2 本次不包含

- 待办截止时间、负责人、优先级、提醒、排序、筛选或同步。
- 将 SnapScribe 变成任务管理工具。
- 批量移动已有外部媒体。
- 自动整理或重命名用户原始媒体。
- 外部直接编辑 `transcript.json` 或 `summary.json` 后自动同步。
- 新增图片理解、工具调用或推理过程展示。
- 修改当前 AI 多模型的顺序故障转移原则。

## 4. 方案选择

采用增量扩展现有模型和项目存储的方案。

### 4.1 采用方案

- AI 模型继续使用现有 `AIModelConfig`，只增加可选的系统预设标识和待配置状态判断。
- 导入策略扩展为三值枚举，移动后的媒体继续作为 SnapScribe 管理的媒体。
- `AISummary.actionItems` 从字符串数组升级为带稳定 ID 和完成状态的对象数组。
- 文本复制在现有页面组件上增加事件协调，不引入富文本编辑器。

### 4.2 未采用方案

不使用“待办文字数组 + 完成索引数组”。删除或重排待办后索引容易错位，迁移和维护成本反而更高。

不把所有摘要内容改造成统一富文本数据。当前只有待办需要编辑状态，全面重构会扩大风险和测试范围。

不直接调用操作系统的简单移动后立刻建立项目。跨磁盘移动本质是复制后删除，直接移动无法为中断恢复和完整性校验提供一致保证。

## 5. GLM 4.7 Flash 默认模型

### 5.1 预设定义

系统预设使用以下固定配置：

```ts
const GLM_47_FLASH_PRESET = {
  presetKey: "glm-4.7-flash",
  name: "GLM 4.7 Flash (免费)",
  vendor: "Custom",
  protocol: "openai-chat",
  baseUrl: "https://open.bigmodel.cn/api/paas/v4",
  modelId: "glm-4.7-flash",
  endpointMode: "auto",
  authType: "bearer",
  timeoutSecs: 60,
  supportsToolCall: true,
  supportsImages: false,
  supportsReasoning: true,
  useCustomProtocol: false,
};
```

用户提供配置中的 `id` 对应 SnapScribe 的 `modelId`。SnapScribe 模型记录自身的 `id` 仍由 UUID 生成，避免与其他模型记录冲突。

当前 AI 总结只使用文本和 OpenAI Chat Completions 兼容请求，因此能力字段作为预设元数据保留，不改变本次请求体，也不在界面增加无效开关。

`endpointMode: "auto"` 继续按现有规则得到：

```text
https://open.bigmodel.cn/api/paas/v4/chat/completions
```

### 5.2 自动加入与幂等迁移

应用读取 `ai-service.json` 后执行一次轻量幂等迁移：

1. 按 `presetKey === "glm-4.7-flash"` 查找预设。
2. 若不存在，创建 GLM 预设并插入列表第一位。
3. 原有模型保持相对顺序，`order` 统一向后移动。
4. 若预设已存在，不重复创建，不覆盖用户已保存的 API Key。
5. 系统可以修复预设的请求地址和模型 ID，但不改写用户自定义显示名称、启停状态和超时时间。

迁移同时覆盖全新安装、空模型列表和已有多个模型三种情况。

### 5.3 默认与待配置状态

- GLM 预设默认启用并位于第一位。
- 未保存 API Key 时，模型行显示中性状态“待配置”，不显示“连通”。
- 缺少必需密钥的模型不进入实际请求尝试，避免每次生成总结都产生可预期的鉴权失败。
- 用户保存 API Key 并测试成功后，状态显示绿色“连通”。
- GLM 具备密钥且启用时，作为列表中的首选模型；失败后仍按现有顺序尝试其他已启用且配置完整的模型。

### 5.4 简化配置

GLM 预设行提供“配置 Key”入口。弹窗默认只显示：

- 模型名称（只读）。
- API Base URL（只读）。
- 模型 ID（只读）。
- API Key（可输入，已保存时显示 `******`）。
- 测试连接。
- 保存。

不向普通用户暴露协议、路径和认证方式。已有通用“编辑模型”能力保留给用户自行添加的模型。

API Key 继续使用现有 DPAPI 本机加密存储，不进入 `ai-service.json`、日志、错误文本或导出文件。

## 6. 导入策略与项目目录

### 6.1 设置数据结构

```ts
type ImportStrategy = "reference" | "copy" | "move";
```

设置页选项顺序：

1. 仅引用原文件（默认/推荐）。
2. 复制到 SnapScribe。
3. 移动到 SnapScribe（便于集中管理）。

“移动到 SnapScribe”下方必须明确说明：导入成功后原位置文件将被删除，SnapScribe 内只保留一份。

该策略仍通过“保存设置”按钮提交，不自动保存。

### 6.2 目录布局

数据根目录保持现有项目集合结构，每个项目是独立目录：

```text
<dataRoot>/
└─ projects/
   └─ <projectId>/
      ├─ project.json
      ├─ transcript.json
      ├─ summary.json          可选
      └─ <original-media-name> 移动或复制后由 SnapScribe 管理的媒体
```

`project.json`、`transcript.json` 和 `summary.json` 仍是应用数据源。媒体文件与这些文档位于同一项目目录，不再要求用户到其他目录寻找。

已有项目中位于 `media/` 子目录的文件保持原路径，不做强制搬迁；新导入项目使用新布局。读取逻辑必须兼容两种布局。

### 6.3 安全移动流程

无论源文件和数据目录是否在同一磁盘，都采用一致的“复制、校验、提交、删除源文件”流程：

```text
验证源文件
  -> 创建项目暂存目录
  -> 复制到同目录临时文件
  -> flush 并关闭目标文件
  -> 校验目标大小，并用 ffprobe 验证目标媒体可读取
  -> 原子重命名为最终媒体文件名
  -> 原子写入 project.json 与 transcript.json
  -> 将项目暂存目录提升为正式项目目录
  -> 删除原位置文件
  -> 自动开始转录
```

删除源文件是最后一步。在此之前任一环节失败：

- 保留原文件。
- 清理未完成的项目暂存目录。
- 不在文件库留下空项目。
- 向用户显示具体失败阶段。

若目标已成功提交但删除源文件失败：

- 不回滚已写入的 SnapScribe 副本。
- 项目标记为“移动未完成”。
- 明确提示原文件仍在原位置，用户可重试删除或手动处理。
- 在问题解决前不得声称移动成功。

### 6.4 文件命名

- 优先保留原始文件名和扩展名。
- 清除 Windows 不允许的路径字符。
- 与项目文档名冲突时添加稳定后缀，例如 `-media`。
- 项目目录由 UUID 命名，项目显示名称仍可独立重命名。

### 6.5 打开当前文件夹

设置页“转录数据保存位置”输入框右侧增加“打开当前文件夹”按钮：

- 打开当前已经保存并生效的 `dataRoot`，不打开尚未保存的草稿路径。
- 目录不存在时先安全创建，再调用系统文件管理器打开。
- 打开失败时显示内联错误或 Toast，不改变设置。
- 使用 Rust/Tauri 命令执行，不由前端拼接 Shell 命令。

## 7. 待办事项编辑

### 7.1 数据结构

```ts
interface ActionItem {
  id: string;
  text: string;
  completed: boolean;
}

interface AISummary {
  schemaVersion: 2;
  projectId: string;
  sourceTranscriptRevision: number;
  generatedAt: string;
  summary: string;
  keyPoints: string[];
  actionItems: ActionItem[];
  model: string;
}
```

本次不增加截止时间、负责人、优先级和额外元数据。

### 7.2 旧数据迁移

读取 `schemaVersion: 1` 或缺少版本的总结时，将每条字符串转换为：

```ts
{
  id: crypto.randomUUID(),
  text: oldText,
  completed: false,
}
```

迁移后的数据在第一次修改待办时写回 `schemaVersion: 2`。仅查看旧总结不强制重写文件。

AI 新生成的 `actionItems: string[]` 在保存前由 Rust 转成结构化待办，AI 不负责生成 ID 或完成状态。

### 7.3 交互规则

每个待办行包含：

- 左侧完成复选框。
- 中间始终可编辑的单行文字区域。
- 右侧仅在悬停或聚焦时显示的删除按钮。

编辑行为：

- 单击文字直接放置光标，不进入额外编辑模式。
- 文字区域默认无明显输入框边框；悬停时显示浅灰背景，聚焦时显示主题紫色描边。
- 失焦自动保存当前文字。
- `Enter` 保存并退出当前编辑；`Esc` 恢复本次编辑前的文字。
- 现有待办被清空后失焦，恢复原文字；删除必须使用删除按钮。
- 新增的空待办失焦时直接丢弃，不写入文件。
- 新增按钮位于列表底部，新建后立即聚焦。
- 删除立即保存，不增加二次确认。
- 勾选完成后立即保存，并对文字显示删除线和弱化颜色；取消勾选恢复正常样式。

### 7.4 保存与并发

待办每次修改通过项目级命令保存完整的最新 `AISummary`，Rust 使用临时文件加原子替换写入 `summary.json`。

前端同一时刻只允许一条待办处于待保存状态。保存期间显示轻量状态，不弹出阻断对话框。保存失败时：

- 保留用户当前输入。
- 显示“保存失败”状态。
- 允许失焦、Enter 或显式重试再次提交。
- 不用旧服务端数据静默覆盖当前文字。

重新生成 AI 总结属于整体替换操作。触发重新生成前，必须等待当前待办保存完成；生成成功后用新待办列表替换旧列表。

## 8. 文本选择与复制

### 8.1 通用原则

转录文本、摘要、关键要点和待办文字都必须允许原生文本选择：

```css
user-select: text;
cursor: text;
```

复制不得修改项目数据，不增加确认步骤。

### 8.2 转录段落

- 单击段落且当前没有文本选区：跳转到该段开始时间。
- 单击时间戳：始终跳转到该段开始时间。
- 鼠标按住拖动形成非空选区：不触发跳转。
- 双击段落：选择并复制整段文字，显示短暂“已复制该段”提示。
- 双击发生在同一段时，第一次点击立即执行该段跳转，第二次点击完成整段复制；不得造成页面滚动、闪烁或跳到其他段。
- 复制内容只包含段落文字，不包含时间戳；导出仍保留原有格式规则。

实现时在跳转前检查浏览器 `Selection`。只要当前选择内容非空，就取消段落跳转。

### 8.3 AI 总结

- 摘要、关键要点和待办均可拖选任意部分。
- `Ctrl+C` 复制当前选区。
- 双击摘要或要点时保持浏览器常规选词行为，不自动复制整个 AI 总结。
- 页面现有“复制全文”按钮继续按当前 Tab 复制完整内容。
- 待办完成样式的删除线只影响显示，不进入纯文本复制结果。

### 8.4 右键复制

文本区域提供确定可用的右键菜单：

- 有文本选区时显示“复制所选文字”。
- 转录段落没有选区时显示“复制整段”。
- AI 总结没有选区时不自动复制整个页面，继续提供现有“复制全文”按钮。

优先使用 WebView 原生复制菜单；若生产 WebView 禁用了原生菜单，则实现仅包含上述复制动作的轻量自定义菜单。不得加入与本需求无关的搜索、翻译或格式操作。

剪贴板写入失败时显示错误提示，不能显示成功状态。

## 10. 状态与错误处理

### 10.1 GLM

- 无 Key：待配置，跳过调用。
- 测试成功：绿色“连通”。
- 鉴权失败、限流、超时、服务错误：沿用现有状态分类和红色错误样式。
- 自动迁移失败：不破坏原模型列表，记录可读错误并允许下次启动重试。

### 10.2 移动导入

- 源文件不可读：不创建项目。
- 目标空间不足：保留源文件并清理暂存文件。
- 复制或媒体校验失败：保留源文件并清理暂存项目。
- 项目文档写入失败：保留源文件，不显示项目。
- 源文件删除失败：保留已提交项目，显示“移动未完成”，不得静默当作成功。

### 10.3 待办

- 保存失败：保留输入和失败状态，可重试。
- 删除失败：恢复被删除行及原顺序。
- 完成状态保存失败：恢复复选框之前状态。
- 总结文件格式无效：不覆盖文件，显示总结读取错误。

### 10.4 剪贴板

- 浏览器剪贴板接口不可用时使用 Tauri 剪贴板能力作为后备。
- 写入失败时显示错误，不改变选区。

## 11. 兼容与迁移原则

1. 所有迁移必须幂等，多次启动不得重复增加 GLM 模型或重复转换待办。
2. 现有模型 UUID、密钥文件和排序在插入 GLM 后保持有效。
3. 现有 `reference`、`copy` 设置值继续正常反序列化。
4. 现有 `media/` 子目录项目继续播放、重新关联和删除媒体。
5. 旧总结在未编辑时仍可正常查看、复制和导出。
6. 版本升级不能自动移动现有用户的外部原文件。
7. 数据迁移失败不得覆盖最后一份可读取配置或项目文档。

## 12. 测试设计

### 12.1 前端测试

- GLM 预设无 Key 显示“待配置”，保存 Key 后仍只显示遮罩。
- GLM 简化弹窗不暴露高级配置。
- 设置页显示三种导入策略和“打开当前文件夹”。
- 待办新增后自动聚焦，失焦保存。
- 待办 Enter 保存、Esc 恢复、空新行丢弃。
- 待办完成后显示删除线，取消完成恢复。
- 待办删除成功与保存失败回滚。
- 转录文本单击跳转。
- 存在非空文本选区时不跳转。
- 双击复制整段且不包含时间戳。
- AI 总结与转录文本支持拖选和右键复制。

### 12.2 Rust 测试

- 空配置和已有配置都只加入一个 GLM 预设。
- GLM 插入第一位且原模型相对顺序不变。
- GLM 无 Key 时从调用快照中跳过，有 Key 时优先调用。
- 旧模型配置缺少 `preset_key` 时兼容读取。
- `Move` 导入成功后目标文件存在、源文件不存在。
