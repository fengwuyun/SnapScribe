## 1. 结论摘要

- 按《Codex_PC端软件开发方案》建立规格驱动框架：`AGENTS.md` + `DEVELOPMENT_SPEC.md` + `UI_DESIGN_SPEC.md` + `docs/`，小任务推进，每步验证。
- 技术栈：Tauri 2 + React + TypeScript + Tailwind CSS + shadcn/ui + Lucide Icons + FFmpeg，目标平台 Windows。
- **推理运行时选型修正**：开发文档写的是 sherpa-onnx + SenseVoiceSmall INT8；工作区实际提供 `funasr-llamacpp-windows-x64` 预编译包（`llama-funasr-sensevoice.exe` 等）。采用后者：同一模型（SenseVoiceSmall）、同为量化本地推理（GGUF q8 ≈ INT8）、零 Python、免去 sherpa-onnx 动态库集成。仅替换推理运行时，架构不变（Rust 子进程调用）。
- **新增需求落地方案**：
  1. 开始转写后，FFmpeg **一次转码 + 切片**：输入文件 → 16kHz/Mono/16bit PCM WAV，按固定时长（默认 60s）切成 N 段；
  2. Rust 顺序逐段调用 `llama-funasr-sensevoice.exe`（段内用 FSMN-VAD 对齐时间戳），每段完成立即通过 Tauri 事件推送该段文本；
  3. 前端订阅事件，Transcript 列表**渐进式追加渲染**，进度条按已转写时长实时推进。

## 3. 核心链路（含新增切分/渐进需求）

```text
用户拖入 / 选择文件
        ↓
React invoke("get_media_info")          ← ffprobe 读取时长/大小/格式
        ↓
React invoke("start_transcription")
        ↓
Rust: 阶段 preparing
  FFmpeg 一条命令完成 提取音轨 + 统一格式 + 切片
  ffmpeg -i in -vn -ac 1 -ar 16000 -c:a pcm_s16le -f segment -segment_time 60 seg_%04d.wav
        ↓
Rust: 阶段 transcribing（循环 N 段）
  每段: llama-funasr-sensevoice -m model.gguf --vad fsmn-vad.gguf -a seg_i.wav --srt
        ↓
  解析 SRT → 时间戳偏移 += i × segment_time → TranscriptSegment[]
        ↓
  emit("transcript://segments", { 新完成的段落 })     ← 每段完成即推
  emit("transcript://progress", { 百分比/已处理时长 })
        ↓
React: 实时追加渲染段落、更新进度
        ↓
emit("transcript://completed", { TranscriptResult })
        ↓
复制全文 / 导出 TXT / 导出 SRT（Rust 写文件）
```

### 设计要点与取舍

- **一次转码即切片**：`-f segment` 在解码输出路径上直接分段，避免"先整条 WAV 再切"的双倍磁盘 IO。音频为 PCM 时每个样本都是关键帧，切割点精确无重编码损失。
- **段内 VAD 时间戳**：每段独立用 `--vad fsmn-vad.gguf --srt`，得到段内语音对齐的细粒度时间戳；全局时间 = 段偏移 + 段内时间。
- **固定窗切割的边界代价**：切割点可能落在词中间（每段最多影响首尾各一个词）。MVP 接受此取舍，记入 ADR；改进方向（静音对齐切割）不在本期。
- **负载控制**：单段 60s 音频在 CPU 上秒级完成，内存占用恒定，不随总时长增长；段数即并行度上限（本期严格串行，保证时间戳单调与取消语义简单）。
- **模型加载开销**：每段冷启动加载一次模型（q8 约 200MB）。若实测开销显著，优化为常驻子进程协议——本期先用逐段调用（实现简单、崩溃隔离好），以实测数据决定是否迭代。

## 4. 事件与数据协议

沿用开发文档 §7 数据结构，新增事件通道：

```ts
// types/transcript.ts —— 与文档一致
interface TranscriptSegment { id: string; start: number; end: number; text: string }
interface TranscriptResult { fileName: string; duration: number; language?: string; segments: TranscriptSegment[] }

// Tauri 事件载荷
type ProgressEvent = {
  stage: "preparing" | "splitting" | "transcribing";
  percent: number;            // 0–100，按已转写时长计算
  processedSeconds: number;
  totalSeconds: number;
  segmentIndex: number;       // 从 1 开始
  segmentCount: number;
};
type SegmentsEvent  = { jobId: string; segments: TranscriptSegment[] };  // 增量新段
type CompletedEvent = { result: TranscriptResult };
type FailedEvent    = { message: string };
```

状态机保持文档 §8 五态不变：`empty → ready → transcribing → completed | error`。"切分中/转录中"作为 `transcribing` 内部的 stage 展示，不增加顶层状态。

Tauri Commands（在文档 §9 基础上细化）：

```rust
select_file() -> Option<PathBuf>
get_media_info(path) -> MediaInfo { fileName, sizeBytes, durationSecs, container }
start_transcription(path) -> jobId          // 异步任务；结果走事件
cancel_transcription(jobId) -> ()           // 杀当前子进程并终止循环
export_txt(segmentsJson, path) -> ()
export_srt(segmentsJson, path) -> ()
save_txt_dialog() / save_srt_dialog()       // 原生另存对话框
resolve_runtime() -> RuntimePaths           // 定位 ffmpeg/ffprobe/model（资源目录优先，其次 PATH）
```

```text
SnapScribe/

├── docs/
│   ├── architecture.md          # 架构与模块职责
│   ├── decisions/               # ADR：001 用 funasr-llamacpp 替代 sherpa-onnx；002 固定窗切片

├── src/                         # React（组件划分按开发文档 §11）
│   ├── components/  AppHeader / DropZone / FileItem / TranscribeProgress /
│   │               AudioPlayer / TranscriptList / TranscriptItem / BottomActionBar / EmptyState / ErrorState
│   ├── hooks/       useTranscription.ts（状态机 + 事件订阅）
│   ├── lib/         tauri.ts / format.ts
│   ├── types/       transcript.ts
│   ├── pages/       Home.tsx
│   └── styles/      globals.css（Design Tokens 原样落地）
├── src-tauri/
│   ├── src/         main.rs / commands.rs / media.rs / ffmpeg.rs / asr.rs / pipeline.rs / export.rs
│   ├── resources/   bin/(ffmpeg·ffprobe·funasr exes)  models/(gguf)   # 发布期放入
```

| 0 | 规格与规则文件落地 | AGENTS.md / DEVELOPMENT_SPEC.md / UI_DESIGN_SPEC.md / docs 就位；git init |

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| HF 模型下载受网络限制 | 脚本支持直连 URL 断点续传；必要时用户手动放置 gguf 到指定目录 |
| 段边界切断词语 | MVP 接受并记录 ADR；后续可用静音检测对齐切割点 |
| 每段冷启动模型加载慢 | 先实测；显著则升级常驻进程协议（pipeline.rs 内聚，接口不变） |
| WebView2 / Tauri 构建环境问题 | 开发机已具备 rustc/node；首次 `cargo check` 即暴露 |
| pnpm 缺失 | 全程使用 npm，不引入 pnpm 依赖 |
